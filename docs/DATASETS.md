# Dataset discovery metadata — 0.18.0

This increment begins long-term roadmap Phase 11. It adds an internal Dataset model,
public catalogue/detail, unified search and a bounded metadata-only importer for
public NCBI GEO Series records. It does not implement all dataset repositories,
experimental file hosting, expression analysis, sample-level browsing or dataset
knowledge-graph projection.

## Source and identity contract

The first supported repository is GEO and the accession namespace is public `GSE`
Series. The [GEO overview](https://www.ncbi.nlm.nih.gov/geo/info/overview.html)
distinguishes submitter Series records from curated DataSets; this importer does
not claim to import curated `GDS` records. Repository/accession identity is unique.

Dataset metadata retain title, source summary, explicitly reported experiment types,
organism names, taxonomy IDs, platform accessions, source-reported PubMed references,
optional repository sample count and provider update date. Mandatory provenance
includes the source identifier (equal to accession), source URL and timezone-aware
retrieval time. Source contact names, emails, addresses and contributor metadata are
not extracted or stored.

Organism labels and taxonomy IDs remain reported metadata rather than automatically
resolved local Organism relationships. Multiple values can be retained without
assuming a name/ID pairing. Tissue, disease, genes and platform technology are not
inferred from title/summary text. An external PubMed reference does not imply that
its citation has been imported locally or that a graph assertion has been created.

## Bounded GEO adapter

`python -m app.cli import-dataset GSE10072` fetches exactly one Series self record
with `targ=self`, `form=text`, `view=brief`. The metadata response must contain one
matching Series header/accession, public status, title and a valid reported update
date. Other entity headers, inconsistent identities, duplicate/invalid GSM sample
IDs, malformed dates and unsupported metadata fail closed. The existing HTTP retry,
timeout and response bounds apply, plus a 2 MB parser limit. Sample counts are
bounded to 100,000 and metadata arrays/values have explicit schema limits.

The sample count is derived from the complete observed list of unique Series GSM
identifiers, not numbers in prose. Missing sample IDs yield an unknown count, not
zero. A repository sample record is not necessarily a patient, independent subject
or analysis-ready expression column. The
[official GEO accession record](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE10072)
is the source for the initial sample, platform and reference metadata.

No linked GSM/GPL records, raw archives, matrices, supplementary files, FTP paths
or arbitrary source URLs are fetched. Data access links open the source landing page
for files and access information. Summary text is displayed as a source statement,
not a conclusion validated or generated by BKP.

Imports are atomic and idempotent by repository/accession. Same-source refresh
updates the current metadata and retrieval timestamp; unchanged content does not
create another record. Refresh locks/reloads the current row. A regressing provider
update date or different source produces a controlled conflict rather than silently
overwriting newer or differently sourced metadata. This is not immutable dataset
versioning or a complete payload archive. Dataset queue jobs and scheduled refresh
are not added; the first importer is an explicit host CLI operation.

## API and interface

- `GET /api/v1/datasets` supports bounded pagination and literal partial filtering
  over accession, title and summary with `q`.
- `GET /api/v1/datasets/{id}` and `/by-accession/{GSE}` return metadata/provenance.
- `POST /api/v1/datasets` requires the existing fail-closed administrator token;
  duplicate identities return 409. No edit/delete endpoint is introduced.

The existing public proxy still blocks writes. The dataset catalogue at `/datasets`
and detail at `/dataset/{id}` show source fields, update date, source-reported
references and a repository access link. Unknown fields remain unavailable. UI
notes distinguish repository sample counts from participants and metadata discovery
from data downloads/analysis.

Unified search/suggestions add a thirteenth `dataset` category with accession,
title and summary matching plus numeric detail links. Array metadata are displayed
on detail rather than claimed as complete search facets. Clients with closed enums
must add the type or use explicit old filters. Graph/relationship types and the
existing scoped quality dashboard are unchanged.

## Migration, tests and rollback

Additive migration `20261112_0015` creates the dataset table, identity/source indexes
and repository/sample-count checks. Existing tables are retained. Downgrade refuses
when dataset rows exist rather than deleting imported metadata. Operational rollback
uses retained old application images with the expanded schema and new migration
service retained; older migration images do not recognize the new revision.

Tests cover metadata-only HTTP parameters, identity/privacy/count/date validation,
idempotent refresh, regressions, source conflicts, pagination, API authorization and
source shape, search/suggestions, JSON/date behavior on PostgreSQL and honest UI
states. Run all existing suites, fresh/restored migrations, model comparison,
Ruff/mypy and frontend test/format/lint/type/build checks before rollout.

A real `GSE10072` import is tested first on the upgraded restored database. Its
reported metadata include 107 repository sample records, GPL96, taxonomy 9606 and
source PubMed reference 18297132. These counts/IDs are source observations, not a
clinical interpretation or a whole-repository coverage claim. No local publications,
genes or disease entities are created by the dataset import. Public loading is
recorded in DATA_STATUS.md after verification.

## Follow-up in 0.19.0

Explicit local PMID resolution and dataset graph navigation are now implemented;
see [dataset citation graph](DATASET_GRAPH.md). Earlier limitations above describe
